# CPU/GPU cost per model and per thread (2026-10-29)

Machine: GTX 1050 Ti (Vulkan) + UHD 630, 8 threads. Release build.
Follows `FPS-REPORT.md` (2026-10-12, lock waits on the UI thread).

## How to reproduce

    cargo run --release -p metal-render --bin render-bench -- --w 1920 --h 1080 --frames 90 --csv out.csv
    ./scripts/perf-scenarios.sh target/perf-scenarios 10   # needs target/release/metal-dash

`render-bench` draws every model through `Renderer::solo_chain_into` (the live
path, no readback) with every expressive float (drive >= 0.4) swept through its
range. Per frame: `model_cpu` (inside `Model::render`), `cpu` (whole call incl.
post chain), `gpu` (queue drain after submit). The first frame is `build`.
`--still` keeps defaults.

`perf-scenarios.sh` launches the real app on port 7977, samples CPU% per thread
from `/proc` while idle and while pulling 720p `/preview.jpg` per selected model,
and saves `GET /perf` + the log.

## Findings

### 1. Models are almost never the CPU problem
102 of 107 models spend **0.10–0.3 ms** of CPU per frame. Only five do real CPU work:

| model | model CPU p50 / p95 (ms) | why |
|---|---|---|
| fineline | 18.1 / 21.7 | software z-buffer + hidden-line + hatching every frame |
| corals | 6.6 / 12.9 | CPU growth sim (+ reseeds while `semilla/forma` move) |
| landscape | 4.3 / 6.8 | CPU mesh rebuild |
| fluid | 3.3 / 6.3 | CPU solver |
| clouds | 1.5 / 3.5 | CPU field |

### 2. GPU: a ~7 ms floor at 1080p, a few very heavy models
Even trivial models cost ~7–8 ms GPU at 1080p: that is the post chain on a 1.06x
overscanned target, not the model. Heaviest (GPU p50, ms): orbit-swarm 119,
monster 115, parallax-cave 105, hairlines 93, phosphor-trace 87, parallax-sky 68,
dotorbit 65, parallax-fields 61, swarmfield 58, blobfield 55; then halftonecmyk,
parallax-city, caustic-weave, water at 26–31. Everything else 7–24.

### 3. First-frame build stalls (CPU, on the calling thread)
monster 4.2 s, bulb 1.8 s, river 1.25 s, room 1.1 s, parallax-cave 1.06 s,
magnet-spikes 0.4 s, fluid 0.31 s. Selecting one of these on air freezes that thread.

### 4. `tone-infer` held ~30% of a core all the time — **fixed**
The basic-pitch worker re-inferred its whole ~2 s window every 2048 samples
(~11/s), and its silence gate (every sample < 1e-4) never fires on a real input's
noise floor, so it never idled. Now: hop 4096 (`LIVE_HOP`) and an RMS < -60 dBFS
gate. Measured idle: **30.7% → 19.9%** of a core.

### 5. Frame-out path costs ~1% CPU per fps
`/preview.jpg` 720p at 27–41 fps used 38–60% of a core on the HTTP thread, while
the model's own CPU was ~0.1 ms: the cost is readback + JPEG encode. A remote
node or monitor at 30 fps pays ~40% of a core on the server.

### 6. UI thread
Idle window ~1% CPU. At startup one 75 ms slow frame: `GET /graph` 30 ms +
`GET /author/songs` 18 ms run on the UI thread's door in the same frame.

## Proposals (ordered by CPU saved per effort)

1. **tone-infer** (done: hop + gate). Next: run inference only while some graph
   on air reads a tone column, and cache the mel/CQT front end so a hop only
   computes the new frames instead of the whole window.
2. **Frame-out**: send raw RGBA/QOI on loopback (crate already has `qoi.rs`) and
   JPEG only off-machine; encode on a worker thread at the consumer's size, and
   skip re-encoding when no client asked since the last frame.
3. **fineline**: cache the projected z-buffer and silhouettes while camera and
   `forma` are unchanged (only time-driven placement moves); run `compose` on a
   worker one frame behind; drop hatching density with output size.
4. **corals/landscape/fluid/clouds**: exclude seed/shape floats from per-frame
   modulation (they reseed every frame); step the sims at a fixed 30 Hz instead
   of per draw.
5. **Build stalls**: warm pipelines for the scene's models on a background
   thread at load (and for the next cued model), not on first draw.
6. **GPU floor**: render models at the output size times a quality factor
   (0.5–0.75 for the heavy list) and upscale in the post pass; for orbit-swarm,
   monster, parallax-*, hairlines, phosphor-trace cap particle/step counts by
   resolution.
7. **UI startup**: move `/graph` and `/author/songs` first loads off the UI
   frame (prefetch on a worker, show when landed).
