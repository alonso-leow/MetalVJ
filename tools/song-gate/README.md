# The song gate

An **offline authoring tool** — not part of the shell, not a client of the
server (the one explicit exception to the "one client" rule). It is a single
file of vanilla JS with no build step and no routes. It lets the operator decide,
per song, the genre, **which animations that song is allowed to use**, and
**which one it prefers**; the router gate reads the JSON it writes and trains
on it.

## What it needs

- `tools/song-gate/models.json` — the animation list, generated by
  `cargo run -p metal-dash --bin catalogue` (it writes both this file and
  `data/songs/catalogue.json`). It is fetched relative to the page.
- `tools/song-gate/demos/<id>.mp4` + `<id>.jpg` — a short looping demo clip
  and its poster, one per animation, shown beside each row. Generated headless
  by `cargo run -p metal-render --bin model-demo -- --out tools/song-gate/demos`.
  Each clip uses the schema's own defaults — the model's resting state and
  colours, no effects — so it shows what the animation is; the poster is a
  mid-clip frame (frame 0 is empty for models that fill over time, and black for
  a transmission before its footage decodes). A transmission (`estela`) is
  pointed at `data/reels/example-footage` (`--footage <name>` to change, `--vary`
  to stress a model with a spread-out float row instead). Optional: the page
  falls back to the name and look line when a clip is missing.
- The songs themselves, opened from disk with the **Open data/audio folder**
  button (`data/audio/`). Nothing is uploaded; playback is a browser
  `blob:` URL of the file you picked.

## How to open it

`file://` pages often refuse both `fetch("./models.json")` and
`localStorage`, so the reliable way is to serve the tool's own folder:

```sh
# from the repo root
python3 -m http.server 8000 --directory tools/song-gate
# then open http://localhost:8000/ in a browser
```

If you do open `index.html` directly from disk and the browser blocks
`models.json`, the page offers a **Pick models.json** button: choose
`tools/song-gate/models.json` by hand. The autosave is wrapped in `try/catch`
and simply does not resume across reloads in that case — the page never throws.

## How to use it

1. **Open data/audio folder** and pick `data/audio`. The list shows the 74
   songs, sorted by number, with `8hz` beside the ones that already have their
   digest.
2. Pick a song, listen (play/pause, seek, ±10 s, next), type its **genre**
   (the field autocompletes over the genres already used), and tick the
   animations it allows. **select all / none** and **copy from the previous
   song** are there for the fast pass. Each animation has a preview clip —
   hover to watch it loop, click to pin it playing. The **☆ star** marks one
   animation as the song's **preferred** pick: it is the animation the router
   favours in each section, and marking it also allows it. Only one preferred
   animation per song; un-ticking the animation clears it.
3. Keyboard: `space` play/pause, `j` previous, `k` next, `n` next unfinished,
   `1`–`9` toggle the first nine animations, `shift`+`1`–`9` mark one
   preferred. Edits autosave in this browser.
4. **Save gate.json**. A song counts as *done* when it has a genre **and**
   allows at least one animation (both are what the router needs); the header
   shows `n/74 done · m with a pick`, and **next unfinished** jumps to the
   first song that is not done yet.
5. Move the downloaded file into place:

```sh
mv ~/Downloads/gate.json data/router/gate.json
```

6. To continue later, **Load gate.json** and pick the file you saved (or the
   one already in `data/router/`). A version-1 file (no `prefer`) loads
   unchanged.

## The file it writes

```json
{
  "version": 2,
  "models": ["geoterrain", "domain", "…"],
  "songs": {
    "01 - Kybba, Ryan Castro, Sean Paul & Busy Signal - BA BA BAD REMIX (Video Oficial)": {
      "genre": "reggaeton",
      "allow": { "geoterrain": true, "domain": false, "…": false },
      "prefer": "geoterrain"
    }
  }
}
```

- `songs` is keyed by the **stem**, the same key the `/author/*` routes use.
- `allow` carries every model id with an explicit `true`/`false`, so the gate
  is a complete record and the router never has to guess a missing key.
- `prefer` is the preferred animation id, or `null` for no preference. It is
  always a member of `allow` (a preference implies allowed). The router uses
  it as a weight: the allowed set is the hard mask, and `prefer` biases the
  pick within it.
- `models` is the animation list the gate was filled against; it is the same
  list as `tools/song-gate/models.json`.
